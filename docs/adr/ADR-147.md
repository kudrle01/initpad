# ADR-147 — Přihlášení je odvolatelná session a uživatel vidí, kde je přihlášený

**Status:** Accepted

**Kontext.** Session byla jen podepsaný JWT v cookie s platností 7 dní.
Odhlášení smazalo cookie v prohlížeči, ale zkopírovaná cookie fungovala dál až
do vypršení. Jedinou serverovou pojistkou byla generace `tokenVersion`, kterou
změna nebo obnova hesla a deaktivace zneplatní pro všechna přihlášení účtu
najednou. Uživatel neměl jak zjistit, kde je přihlášený, ani ukončit jedno cizí
přihlášení. Audit z 9. října 2026 to vedl jako nízký nález.

**Rozhodnutí.**

1. Každé přihlášení (heslo, GitHub, registrace, aktivace, změna hesla) vytvoří
   řádek `UserSession` s generací účtu, zkráceným `User-Agent` a expirací 7 dní.
   JWT nese jeho ID v claimu `sid`.
2. Guard, OIDC autorizace pro Gitea i GitHub callback ověřují session stejnou
   službou `SessionsService`: řádek musí patřit účtu z tokenu, nesmí být
   ukončený ani prošlý a generace účtu se musí shodovat.
3. `POST /api/auth/logout` ukončí session na serveru, ne jen cookie.
4. `GET /api/auth/sessions` vypíše aktivní přihlášení účtu. Uživatel může
   ukončit jedno cizí (`DELETE /api/auth/sessions/:id`) nebo všechna ostatní
   (`POST /api/auth/sessions/end-others`). Aktuální session se ukončuje
   odhlášením. Ukončení se zapíše do platformního auditu jako
   `auth.sessions_ended` s počtem ukončených přihlášení.
5. Nastavení účtu ukazuje sekci Přihlášené prohlížeče s prohlížečem, systémem a
   časem přihlášení.
6. Token vydaný před touto změnou nemá `sid` a platí do svého vypršení, nejdéle
   7 dní. Odhlášení s ním ukončí všechna přihlášení účtu, protože jeho session
   nejde ukončit samostatně. Prošlé řádky se mažou při dalším přihlášení.

**Důsledky.** Odhlášení a ukončení session platí okamžitě na všech replikách
API. Ověření požadavku čte místo jednoho řádku účtu jeden řádek session s
účtem, takže počet dotazů zůstává stejný. Během prvních 7 dní po aktualizaci
přehled nezobrazí prohlížeče přihlášené dřív.

**Testování.** Unit testy pokrývají vydání tokenu s řádkem session a zkrácení
`User-Agent`, odmítnutí ukončené, prošlé, cizí a chybějící session v guardu,
odhlášení jedné session i odhlášení starým tokenem, výpis a ukončení ostatních
přihlášení a webovou sekci včetně pojmenování prohlížečů. Živá zkouška nad
PostgreSQL 16 se skutečným API: dvě přihlášení, ukončení druhého z prvního
(druhé pak dostalo 401), odmítnutí ukončení aktuální session, zkopírovaná
cookie po odhlášení dostala 401 a audit zapsal `auth.sessions_ended`. Zkouška
odhalila chybějící `@Inject` u služby session, která v unit testech zůstala
skrytá.

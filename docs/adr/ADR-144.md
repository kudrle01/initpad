# ADR-144 — Platformní obrazy běží s nejmenšími oprávněními a CI je skenuje na zranitelnosti

**Status:** Accepted

**Kontext.** Audit z 9. října 2026 našel u obrazů platformy čtyři mezery:

- Web spouštěl nginx jako root. V SaaS profilu proto potřeboval capabilities
  `CHOWN`, `SETGID`, `SETUID` a `NET_BIND_SERVICE` a v self-hosted profilu
  neměl `cap_drop` ani `no-new-privileges`.
- Obrazy Agenta a Supervisoru obsahovaly zkompilované testy (`dist/*.test.js`).
- Žádný obraz platformy ani lockfile šablony se neskenoval na známé
  zranitelnosti. Model hrozeb přitom skenování image uváděl jako hotové a audit
  Composeru jako součást release kontrol, ačkoli nikde neběžel.
- `docker:27.5.1-cli`, ze kterého Supervisor bere Docker CLI a Compose, je z
  ledna 2025.

Zkušební sken (Trivy 0.74.0) ukázal opravitelné HIGH a CRITICAL nálezy i v
nejnovějších base obrazech: v npm, které Node obraz přibaluje (`tar`,
`brace-expansion`, `sigstore` a další), v Alpine balíčcích nginx obrazu
(`libexpat`, `pcre2`, `tiff`) a 40 nálezů v Go knihovnách starého Docker CLI a
Compose.

**Rozhodnutí.**

1. Web obraz spouští nginx jako uživatele `nginx` (uid 101). Vlastní hlavní
   konfigurace nemá direktivu `user`, pid soubor i dočasné soubory zapisuje do
   `/tmp`. Port 80 zůstává, protože Docker od verze 20.10 nastavuje v síťovém
   namespace kontejneru `net.ipv4.ip_unprivileged_port_start=0`. Oba compose
   profily dávají webu `cap_drop: [ALL]`, `no-new-privileges` a jediný tmpfs
   `/tmp`, žádnou capability nevracejí.
2. Access log webu zapisuje cestu bez query stringu a bez hlavičky `Referer`,
   protože obojí může nést jednorázový kód, třeba OAuth kód nebo token ve
   starém odkazu (ADR-143).
3. Runtime obrazy API, Agenta a Supervisoru neobsahují npm, npx, corepack ani
   yarn. Produkční závislosti instaluje samostatná stage a runtime stage je jen
   zkopíruje. `migrate.js` spouští Prisma CLI přímo přes Node místo `npx`.
4. Build Agenta a Supervisoru maže zkompilované testy z `dist`.
5. Runtime stage všech obrazů spouští `apk upgrade`, takže obsahují opravy,
   které Alpine vydal po base obrazu. Base obrazy jsou připnuté na digesty z
   konce září 2026 a Supervisor bere Docker CLI 29.8.0 s Compose 5.5.1.
6. Workflow `container-images.yml` po sestavení skenuje obrazy API, webu,
   Agenta a Supervisoru a lockfily šablon (npm včetně vývojových závislostí,
   Composer, pip) nástrojem Trivy připnutým digestem. Opravitelná zranitelnost
   HIGH nebo CRITICAL build zastaví. Workflow běží při změně obrazů nebo šablon
   a jednou týdně, protože nové advisories vznikají i bez změny repozitáře.
   Trivy běží jako obraz připnutý digestem, ne jako GitHub Action s
   přepisovatelným tagem.
7. Přijatý nález patří do `.trivyignore.yaml` s cestami, zdůvodněním a datem
   expirace, stejně jako výjimky npm auditu (ADR-127). Po expiraci ho Trivy
   hlásí znovu a sken selže. První dvě výjimky se týkají Go 1.26.8 v Docker CLI
   Supervisoru: obě CVE jsou DoS proti Go serverům a Supervisor CLI používá
   jen jako klienta lokálního Docker socketu bez TLS. Třetí výjimka přibyla
   týž den, když databáze zranitelností ohodnotila jako závažné další CVE ze
   stejné opravy Go: DoS záplavou rámců SETTINGS v HTTP/2, které oba programy
   s lokálním socketem nepoužívají. Všechny tři platí do 9. listopadu 2026.
   Build CLI s Go 1.26.9 vyšel 9. října a připne se, až bude dva týdny starý.

**Důsledky.** Kompromitovaný nginx nemá v kontejneru root ani žádnou
capability. Runtime obrazy jsou menší a nenesou nástroje, které umí stahovat a
spouštět kód. Webový obraz tohoto releasu funguje i se staršími compose
soubory, které Supervisor při aktualizaci ponechá. Opačně to neplatí: web
obraz do verze 0.2.16 se v novém profilu bez capabilities nespustí, proto se
nasazuje obraz ze stejného releasu jako compose soubor. `apk upgrade` dělá
build méně reprodukovatelný; release je dál identifikovaný digestem a
podepsaný.

API zůstává rootem bez dalších změn. V self-hosted profilu drží Docker socket,
což je stejné oprávnění jako root na hostu, a čte šablony připojené z hostu. V
SaaS profilu má odebrané všechny capabilities a čte secrety, které projekce
zapisuje jen pro roota; přechod na jiného uživatele vyžaduje změnit práva
těchto souborů a je samostatná práce. Release workflow obrazy znovu neskenuje,
spoléhá na týdenní a změnový sken větve `main`.

**Testování.** Kontraktní test hlídá uživatele a konfiguraci nginx, formát
access logu, compose nastavení webu, odstranění npm a testů z obrazů, volání
Prisma bez `npx`, sken v CI a tvar výjimek. Živá zkouška: webový obraz běžel
jako uid 101 s prázdnými capability sadami, read-only kořenem a jen `/tmp`,
servíroval SPA i `/api/` a v logu neměl query string. API obraz bez npm
aplikoval nad PostgreSQL 16 všech 67 migrací a nastartoval. Agent a Supervisor
hlásí verzi, Compose 5.5.1 ze Supervisoru provedl `up --no-deps --no-build`,
`ps -q`, `exec -T` i výměnu obrazu přes override. Skeny API, Agenta, Supervisoru
s výjimkami a lockfilů šablon prošly; sken s prošlou výjimkou selhal. Alpine
repozitáře byly v testovacím prostředí blokované, takže `apk upgrade` a sken
webu po něm ověří až CI.

# ADR-153 — SaaS nespouští součásti self-hosted Gitey a install.sh SaaS neinstaluje

**Status:** Accepted

**Kontext.** SaaS edice používá GitHub a nemá vlastní Gitea (ADR-132). API v ní
přesto vystavovalo OIDC provider (`/api/.well-known/openid-configuration`,
`/api/oauth/*`), který slouží jen k přihlášení do vestavěné Gitey, a příjem
systémových webhooků Gitey (`/api/scm/webhook`). Produkční kontrola konfigurace
kvůli nim vyžadovala `INITPAD_OIDC_CLIENT_SECRET` a `INITPAD_SCM_WEBHOOK_TOKEN`,
takže SaaS profil a staging museli tyto secrety generovat a projektovat, i když
je nic nepoužívalo. `install.sh` s `INITPAD_EDITION=saas` spustil self-hosted
stack s Gitea, MinIO, runnerem a Docker socketem v SaaS edici a vypsal
zastaralou hlášku. Audit z 9. října 2026 obojí uvedl v kapitole o nastavení.

**Rozhodnutí.**

1. API registruje `OidcModule` a `ScmWebhookController` jen v self-hosted
   edici. V SaaS tyto cesty neexistují.
2. Produkční kontrola zástupných hodnot `INITPAD_OIDC_CLIENT_SECRET` a
   `INITPAD_SCM_WEBHOOK_TOKEN` platí jen pro self-hosted edici.
3. SaaS profil (`saas.compose.yml`, `.env.saas.example`, `saas-check.sh`) ani
   staging projekce secretů tyto dva secrety nemají.
4. `install.sh` s `INITPAD_EDITION=saas` skončí chybou s odkazem na
   `saas.compose.yml` a `SAAS_STAGING.md`.

**Důsledky.** Veřejné SaaS API má o dvě skupiny endpointů méně a staging o dva
secrety méně. Existující `.env` SaaS stagingu s proměnnými `_FILE` pro tyto
secrety dál funguje, Compose je ignoruje; secrety lze ze správce secretů
odstranit. Self-hosted instalace se nemění.

**Testování.** Test konfigurace ověřuje, že SaaS produkce projde se zástupnými
hodnotami obou secretů a self-hosted produkce s nimi selže. Kontraktní testy
SaaS profilu a staging kitu ověřují, že profil, příklad prostředí ani
projekce tyto secrety neobsahují. Syntaxi `install.sh` ověřuje repository
audit.

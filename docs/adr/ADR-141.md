# ADR-141 — Klíč pro šifrování dat je samostatný, jde vyměnit a nečitelná hodnota je chyba

**Status:** Accepted

**Kontext.** InitPad šifruje v databázi AES-256-GCM hesla a klíče serverů,
Git a GitHub tokeny, secret proměnné aplikací a čekající e-maily. Audit z
9. října 2026 našel v této vrstvě čtyři slabiny:

- Bez `INITPAD_ENCRYPTION_KEY` se klíč odvodil z `INITPAD_JWT_SECRET`, takže
  jeden secret podepisoval sessions i šifroval data.
- `decryptSecret` při chybě vrátil prázdný řetězec. Po změně klíče tak
  nasazení tiše dostalo prázdné secrety aplikace a servery prázdné heslo, bez
  jakékoli chyby.
- Klíč nešlo vyměnit: chyběl způsob, jak číst hodnoty pod starým klíčem a
  převést je na nový.
- Hodnoty uložené před zavedením šifrování zůstávaly v databázi čitelné.

Kontrola produkční konfigurace navíc odmítala jen několik doslovných výchozích
hodnot. Zástupná hodnota z `apps/api/.env.example` i krátký klíč prošly.

**Rozhodnutí.**

1. Klíč je jen `INITPAD_ENCRYPTION_KEY`. Produkční API bez něj nenastartuje a
   chybová zpráva popíše převod instalace, která data šifrovala JWT secretem:
   nastavit jeho hodnotu jako `INITPAD_ENCRYPTION_KEY` a vygenerovat nový
   `INITPAD_JWT_SECRET`. Oba klíče se v produkci musí lišit.
2. `decryptSecret` hodnotu, kterou žádný nastavený klíč neotevře, ohlásí
   chybou `SecretDecryptionError` s popisem, o jaký credential jde. Místa, která
   si umí opatřit nový credential, ji berou jako chybějící: Git token se vydá
   znovu a GitHub požádá o nové propojení.
3. `INITPAD_ENCRYPTION_KEY_PREVIOUS` obsahuje klíče, které hodnoty jen čtou.
   Zapisuje se vždy současným klíčem. Klíč, kterým hodnota šla zašifrovat,
   pozná GCM tag, takže formát `enc:v1:` zůstává.
4. Každá replika API po startu na pozadí převede nešifrované hodnoty na
   šifrované. Během výměny klíče projde všechny šifrované hodnoty a přešifruje
   ty pod předchozím klíčem. Každý zápis je podmíněný původní hodnotou, takže
   souběžná změna ani druhá replika nic nepřepíše. Nečitelné hodnoty zaloguje
   jako `secret.unreadable`. Když jsou všechny hodnoty pod současným klíčem,
   zaloguje, že `INITPAD_ENCRYPTION_KEY_PREVIOUS` jde odstranit.
5. Produkční kontrola vyžaduje u `INITPAD_JWT_SECRET`, `INITPAD_ENCRYPTION_KEY`
   a `INITPAD_ENCRYPTION_KEY_PREVIOUS` aspoň 32 znaků. Odmítá zástupné hodnoty
   obsahující `zmen-me`, `change-me`, `changeme` nebo `__GENERATE__`, i u
   `INITPAD_SCM_WEBHOOK_TOKEN` a `INITPAD_OIDC_CLIENT_SECRET`. Instalátor
   generuje 48 hexadecimálních znaků.

**Důsledky.** Změněný nebo chybějící klíč se projeví chybou s názvem
credentialu, ne nefunkčním nasazením. Server nebo secret proměnnou, kterou
žádný klíč neotevře, musí uživatel zadat znovu. Výměna klíče je postup ve
třech krocích popsaný v `deploy/OPERATIONS.md` a nevyžaduje výpadek. SaaS
předává předchozí klíč souborem (`INITPAD_ENCRYPTION_KEY_PREVIOUS_FILE`).
Nešifrovaná hodnota zůstává čitelná do prvního startu nové verze; potom ji
API převede.

**Testování.** Unit testy ověřují chybu místo prázdné hodnoty, čtení pod
předchozím klíčem a přešifrování, převod nešifrované hodnoty, průchod 151
hodnot po dávkách včetně jedné nečitelné, ochranu proti přepsání hodnoty
změněné během převodu a produkční kontrolu chybějícího, sdíleného, krátkého a
zástupného klíče. Živá zkouška nad PostgreSQL 16 s migracemi: běžný start
převedl nešifrovaný Git token a heslo serveru, prázdný token a `NULL` nechal
být; výměna klíče přešifrovala tři hodnoty, další průchod už žádnou a všechny
hodnoty šly přečíst jen novým klíčem.

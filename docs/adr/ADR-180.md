# ADR-180 — Workload s přímými porty dostává pevný hostitelský port od Agenta

**Status:** Accepted

**Kontext.** Agent vytvářel kandidáta v režimu přímých portů s
`HostPort: ''`. Docker pak port přidělí náhodně, ale přidělí ho znovu při
každém startu kontejneru. Po restartu kontejneru, Dockeru nebo serveru
(`unless-stopped`) proto aplikace běžela na jiném portu, než jaký InitPad
uložil do URL prostředí (ověřeno: 32768 → 32769 → 32770). Uživatel viděl
odkaz, který nikam nevede.

**Zvažované varianty.**

1. _Agent hlásí aktuální porty v heartbeatu a API přepočítá URL._ Vyžaduje
   novou část heartbeat protokolu a novou API logiku. Starší API by pole
   odmítlo (`forbidNonWhitelisted`), takže by se musela zavádět přes vyjednání
   verze. URL se navíc i tak mění při každém restartu, záložky a odkazy sdílené
   v týmu přestanou platit a mezi restartem a dalším heartbeatem je URL
   neplatná.
2. _Agent přidělí konkrétní volný port._ Docker si explicitní `HostPort`
   pamatuje v `HostConfig` a při restartu ho použije znovu. Nemění se
   protokol ani API: výsledek jobu už `hostPort` nese a API z něj URL skládá.

**Rozhodnutí.** Varianta 2.

- Port se vybírá z rozsahu `INITPAD_AGENT_DIRECT_PORT_RANGE` (výchozí
  `30000-32767`, mimo linuxový ephemeral rozsah 32768–60999, ve kterém jádro
  přiděluje odchozí spojení).
- Obsazené porty Agent zjistí z `GET /containers/json?all=1`: publikované porty
  běžících kontejnerů a label `com.initpad.host-port` u zastavených workloadů
  InitPadu, které si port drží pro příští start.
- Hledání začíná na pozici odvozené z hashe identity workloadu. Projekt tak
  při redeployích střídá nejvýš dva porty (kandidát běží souběžně se starou
  revizí, proto nemůže převzít její port) a neputuje celým rozsahem.
- Port obsazený procesem mimo Docker se pozná až při startu (`port is already
allocated`). Agent pak kandidáta smaže a zkusí další volný port, nejvýš pětkrát.
- Režim managed gateway se nemění: port na loopbacku slouží jen health checku
  a upstream brány je název kontejneru.

**Důsledky.** URL přežije restart kontejneru i serveru. Existující kontejnery
s náhodným portem zůstanou, dokud se prostředí znovu nenasadí. Firewall stačí
otevřít pro nastavený rozsah. Změna je jen v Agentovi (vyžaduje release Agenta
0.17), starší Agent se chová jako dřív.

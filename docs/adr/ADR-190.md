# ADR-190 — Zrcadla CI akcí mají vypnuté Actions

**Status:** Accepted

Upravuje [ADR-171](./ADR-171.md).

**Kontext.** Od verze 0.2.35 zakládá `install.sh` v Gitee pull mirrory akcí
z `deploy/runner/actions-mirror` (ADR-171). Gitea 1.22 zapíná unit Actions
každému novému repozitáři, tedy i zrcadlu, a `POST /repos/migrate` nemá volbu,
která by ho vynechala. Synchronizace zrcadla se v Gitee hlásí jako push, takže
spouští upstream workflow akcí, a z výchozí větve si Gitea registruje i jejich
plánovaná workflow. Globální runner InitPadu přitom bere čekající joby ze všech
repozitářů: Gitea 1.22 filtruje joby podle unitu Actions jen u runneru
vázaného na vlastníka. Na lokálním labu s platformou 0.2.47 se tak z pěti
zrcadel nahromadily stovky jobů a CI projektů se k runneru nedostalo. Lab byl
opraven ručně: zrcadlům se vypnuly Actions a zrušilo se 965 čekajících jobů.

**Možnosti.** (a) Po založení zrcadlu vypnout Actions přes API
(`PATCH /repos/{owner}/{repo}` s `has_actions: false`), stejně jako to API už
dělá u odpojeného repozitáře. (b) Vyřadit Actions z `DEFAULT_REPO_UNITS`
v Gitee. Změnilo by to výchozí stav všech nových repozitářů včetně těch, které
uživatelé zakládají nebo importují sami, a existující zrcadla by neopravilo.
(c) Registrovat runner jen pro vybrané vlastníky. Projekty ale leží v účtech
a organizacích mnoha vlastníků, takže InitPad potřebuje globální runner.

**Rozhodnutí.** Varianta (a).

1. `ensure_action_mirror` pošle `PATCH` s `{"has_actions":false}` po založení
   zrcadla i u zrcadla, které už existuje. Děje se to při každém běhu
   `install.sh`, takže se opraví i zrcadla založená verzemi 0.2.35 až 0.2.47.
   Opakované vypnutí nic nemění.
2. Když Gitea vypnutí odmítne, instalátor vypíše varování a zrcadla
   nepoužije, stejně jako při jiné chybě zrcadla.
3. Při `INITPAD_CI_ACTIONS_MIRRORS=off` instalátor zrcadla nezakládá, ale
   v těch, která v Gitee zůstala z dřívějška, Actions vypne.
4. Repozitáře projektů se nemění. API jim Actions zapíná samo při založení.

**Důsledky.** Vypnutí zastaví nové běhy ze synchronizací a Gitea přitom smaže
plány workflow zrcadla. Joby, které čekaly už předtím, globální runner dál
bere. Gitea je sama zruší po `ABANDONED_JOB_TIMEOUT` (výchozí hodnota 24 h,
kontrola každých 6 h). Instalátor je neruší, protože Gitea 1.22 nemá API pro
zrušení běhu a zápis do její databáze za běhu by byl zbytečné riziko.
Aktualizace přes Supervisor (**Platform updates** v administraci) vyměňuje jen
images a `install.sh` nespouští. Instalace s dřívějšími zrcadly proto opraví až jeden běh
`./install.sh` z checkoutu, který tuto změnu obsahuje.

**Testování.** Behaviorální testy v
`scripts/self-hosted-install-contract.test.mjs` spouštějí skutečné funkce
`install.sh` proti podvržené Gitea API. Existující zrcadlo dostane
`has_actions: false` při každém běhu, nové až po `POST /repos/migrate`,
zrcadlo s odmítnutým vypnutím se nepoužije a při vypnutých zrcadlech se Actions
vypnou jen v těch existujících. Na instalátoru 0.2.47 všechny čtyři testy
selžou. Živě na jednorázové Gitee 1.22 se stejným digestem jako v
`docker-compose.yml`, mimo běžící lab: funkce z 0.2.47 založila zrcadlo
`actions/checkout` s `has_actions: true`. Opravený `mirror_ci_actions` mu
Actions vypnul (unit zmizel z `repo_unit`), ověřil commit připnutý šablonami
a zapsal adresu zrcadla. Druhý běh nic nezměnil. Při
`INITPAD_CI_ACTIONS_MIRRORS=off` vypnul Actions i v ručně znovu zapnutém
zrcadle a nově založené zrcadlo mělo Actions vypnuté hned po prvním běhu.
Celý `install.sh` na čistém hostu ani lab tuto změnu zatím neprošly.

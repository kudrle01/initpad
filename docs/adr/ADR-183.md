# ADR-183 — Destruktivní migrace potřebují výjimku a release s nimi nesmí slibovat rollback images

**Status:** Accepted

**Kontext.** Manifest podepsaného releasu vždy tvrdil
`migrationMode: expand-contract` a `rollback: image-compatible`. Nikdo to
nekontroloval, přitom historie obsahuje `DROP COLUMN` i `SET NOT NULL`. Při
selhání po fázi `api` by Supervisor spustil staré API nad novou databází.

**Rozhodnutí.**

1. `scripts/prepare-platform-release.mjs` (`migrationPolicy`) projde všechny
   migrace. Za destruktivní považuje `DROP TABLE/COLUMN/TYPE/SCHEMA/VIEW`,
   `RENAME`, `ALTER TYPE`, změnu typu sloupce a `SET NOT NULL`. `DROP INDEX`
   a `DROP CONSTRAINT` schéma jen uvolňují a zůstávají povolené.
2. Každá destruktivní migrace potřebuje záznam v
   `apps/api/prisma/destructive-migrations.json` s důvodem a verzí releasu.
   Hodnotu `historical` smí mít jen migrace do 0.2.35. Test v
   `npm run test:release-tools` hlídá politiku už v PR, ne až při releasu.
3. Release, který destruktivní migraci dodává, má v manifestu
   `migrationMode: contract`, `rollback: restore-required`. API i Supervisor
   jiné kombinace odmítnou.
4. Supervisor si u takové operace poznamená `restoreRequired`. Selhání po
   fázi `api` už nevrací staré images. Zapíše `recovery-failed` s cestou
   k záloze a odkazem na `restore.sh` a předchozí descriptor ponechá. Stejně
   se chová recovery po restartu hosta i `initpad-install-release.sh`.

**Důsledky.** Starší Supervisor (≤ 0.2.35) contract release odmítne jako
neplatný manifest. Na takový release je pak potřeba přejít přes
`initpad-install-release.sh`. To je záměr, protože starší Supervisor
bezpečný postup nezná.

**Testování.** node:test pokrývá detekci příkazů, odmítnutí migrace bez
výjimky, falešné `historical`, manifest contract releasu a pravidla Supervisoru
pro rollback. Jest pokrývá validaci manifestu v API.

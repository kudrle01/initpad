# ADR-133 — Příjem artefaktu plní lokální Docker daemon jen pro vlastní nasazení control plane

**Status:** Accepted

**Kontext.** Podle ADR-059 se ověřený archiv image po uložení do object store
vždy načetl také do lokálního Docker daemonu control plane. Veřejný SaaS profil
žádný daemon nemá a mít nesmí, protože přístup k němu odpovídá právům root na
hostu. První průchod na stagingu s releasem 0.2.14 proto selhal: CI doběhlo,
archiv byl uložen, ale příjem skončil chybou o nedostupném daemonu a artefakt
zůstal ve stavu `failed`. Stejnou kontrolu vyžadovalo i ruční opakování
nasazení, takže chybu nešlo obejít. Self-hosted edice daemon má, a proto se
chyba neprojevila dříve.

Lokální kopie přitom není zdrojem pravdy. Agent si archiv stahuje z object
store sám a prostředí, která control plane nasazuje vlastním daemonem, si image
před nasazením umí obnovit z object store.

**Rozhodnutí.** Lokální Docker daemon je pouze cache pro prostředí, která
control plane nasazuje sám, tedy vestavěný Docker target a extrakci pro SFTP.

1. Příjem artefaktu načte image do lokálního daemonu jen tehdy, když jej
   potřebuje bezprostředně následující nasazení prostředí `dev`. Prostředí
   `dev` na Docker targetu uživatele s Agentem lokální kopii nevyžaduje.
   Projekt bez prostředí `dev` ji při příjmu také nevyžaduje.
2. Ostatní prostředí si image obnoví z object store až při vlastním nasazení.
   Tento krok už existuje a u prostředí s Agentem se neprovádí.
3. Ruční opakování nasazení na target s Agentem ověří pouze to, že je artefakt
   uložen v object store. Když uložen není, obnoví se z GitHub Actions jako
   dosud.
4. Ověření identity archivu před uložením zůstává beze změny a daemon
   nevyžaduje.

Bod 6 v ADR-059 tím přestává platit v části, která ukládá načíst image do
lokálního daemonu při každém příjmu. Ostatní části ADR-059 platí dál.

**Důsledky.** Veřejný SaaS doručí artefakt z GitHub Actions přes object store
až k Agentovi bez Docker daemonu v control plane. Self-hosted instalace s
vestavěným targetem pro `dev` se chová jako dosud. Projekt, jehož `dev` běží
přes Agenta a jiné prostředí přes vestavěný target, načte image do daemonu až
při nasazení tohoto prostředí, takže první takové nasazení trvá déle. Control
plane zároveň přestává ukládat image, které sám nikdy nespustí.

Nasazení na SFTP ve veřejném SaaS zůstává nefunkční. Extrakce souborů z image
daemon vyžaduje a selže až při nasazení daného prostředí, nikoli při příjmu
artefaktu. Extrakce bez daemonu je samostatná budoucí práce.

**Testování.** Unit testy pokrývají příjem pro `dev` s Agentem a pro projekt
bez `dev`, při kterém by jakýkoli dotyk daemonu skončil chybou, a ruční
opakování nasazení pro uložený i neuložený artefakt. Stávající testy příjmu
pro vestavěný target a obnovy z object store zůstávají. Živé ověření na
veřejném stagingu vyžaduje release s touto změnou.

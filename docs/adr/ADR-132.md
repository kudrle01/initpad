# ADR-132 — Staging veřejného SaaS tvoří nízkonákladová sestava vyměnitelných externích služeb

**Status:** Accepted

**Kontext.** SaaS profil z ADR-120 záměrně nepřibaluje databázi, object store,
správce secretů, edge ani observability backend. Bez konkrétního prostředí proto
nelze provést živou acceptance ani GitHub App E2E, které vyžaduje veřejný HTTPS
origin. Staging slouží diplomovému pilotu s minimálním rozpočtem a bez školní
infrastruktury. Nesmí ale zavést závislost aplikačního kontraktu na jednom
dodavateli.

**Rozhodnutí.** Staging je neveřejný pilot složený z těchto vrstev:

| Vrstva             | Volba                                             | Rozhraní vůči InitPadu                 |
| ------------------ | ------------------------------------------------- | -------------------------------------- |
| Doména a DNS       | vlastní doména se zónou u Cloudflare              | `INITPAD_PUBLIC_URL`                   |
| Edge, WAF a DDoS   | Cloudflare Free s Cloudflare Tunnel               | HTTP na `127.0.0.1:8080`               |
| Host control plane | jedna malá Linux VM s Dockerem (DigitalOcean)     | `saas.compose.yml`                     |
| PostgreSQL         | Supabase Free                                     | soubor s `DATABASE_URL`                |
| Object store       | Cloudflare R2, náhradně Backblaze B2              | S3 API a soubory s klíči               |
| Secrety            | Infisical Cloud a jeho Agent zapisující soubory   | položky `*_FILE`                       |
| SMTP               | Brevo Free                                        | SMTP se STARTTLS a soubor s heslem     |
| Observability      | Grafana Cloud Free za OpenTelemetry Collectorem   | OTLP/HTTP a JSON logy kontejnerů       |
| Agent target       | stroj provozovatele s odchozím spojením           | Agent protokol                         |

Každou vrstvu lze nahradit jinou službou se stejným rozhraním beze změny kódu.
Host nemá veřejně otevřený port aplikace; jedinou cestou je tunel z edge.
Default-deny egress se vynucuje na hostu, protože firewall poskytovatele VM
neumí pravidla podle doménových jmen.

**Důsledky.** Sestava má vědomé odchylky od provozního minima a acceptance je
musí uvést, ne skrýt:

- retence Grafana Cloud Free je kratší než výchozí minimum v
  `docs/OBSERVABILITY.md`;
- Supabase Free nemá zálohy poskytovatele, obnova se dokládá logickým dumpem;
- Cloudflare k hlavičce `X-Forwarded-For` připisuje a nenahrazuje ji; správné
  určení klientské adresy při dvou důvěryhodných hopech se musí prokázat živě;
- bezplatný object store je menší než výchozí kvóta artefaktů jednoho
  workspace, proto se kvóta na stagingu snižuje;
- čtení commitů a stavu pipeline se neukládá do cache. Podle kódu se proto
  jako první vyčerpá hodinový limit GitHub API jedné instalace, a to řádově
  při deseti až dvaceti současně otevřených detailech projektu. Jde o odhad,
  který load acceptance z ADR-124 neměří.

Staging nepřipouští nedůvěryhodné uživatele a jeho výsledky nejsou důkazem
produkční kapacity ani dostupnosti.

**Testování.** Rozhodnutí samo nic nenasazuje. Jeho ověřením je `saas-check.sh`,
kroky ze `deploy/SAAS_ACCEPTANCE.md` a staging acceptance z
`docs/OBSERVABILITY.md` provedené na této sestavě.

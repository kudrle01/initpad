# ADR-140 — Šablony předávají kontext CI jako data, nemají klíče v kódu a dodávají závislosti bez známých zranitelností

**Status:** Accepted

**Kontext.** Audit šablon z 9. října 2026 našel několik slabin, které dědí
každý nově vygenerovaný projekt:

- Workflow vkládala `${{ github.ref_name }}` a další výrazy přímo do shellu
  a do JSON callbacku. Název větve s uvozovkami nebo `$(…)` by se spustil jako
  kód nebo rozbil tělo požadavku.
- Django mělo `SECRET_KEY = "dev-<název projektu>-change-me"`. Kdo znal název
  projektu, znal i klíč, kterým aplikace podepisuje data.
- Python šablony pinovaly jen přímé závislosti a Django 5.1 je mimo podporu.
  gunicorn 22 měl známou zranitelnost request smuggling.
- Lockfily všech pěti JavaScriptových šablon obsahovaly známé zranitelnosti,
  u `next` a `proxy-addr` kritické. Lockfile Laravelu měl 20 advisories v
  `guzzlehttp/guzzle`, `league/commonmark`, `league/flysystem` a
  `laravel/framework`.
- Dependabot hlídal jen npm v kořeni repozitáře, ne závislosti šablon.

**Rozhodnutí.**

1. Workflow šablon dostávají kontext (`CI_REPOSITORY`, `CI_SHA`, `CI_REF`,
   `CI_RESULT`) i secrety přes `env:` a těla callbacků skládají příkazem
   `jq --arg`. Výraz `${{ … }}` stojí jen na řádcích mapování `env:`, což hlídá
   test kontraktu šablon. Převod pro GitHub (ADR-049, ADR-139) zachovává stejný
   tvar a ID i digest artefaktu předává také přes `env:`.
2. Django čte klíč z `DJANGO_SECRET_KEY`. Bez něj použije při každém startu nový
   náhodný klíč, takže žádný klíč není v obrazu ani v repozitáři; gunicorn běží
   s `--preload`, aby ho sdílely všechny workery. `DJANGO_ALLOWED_HOSTS`
   omezí povolené hosty. Je to stejný postup jako u `APP_KEY` Laravelu a
   `APP_SECRET` Symfony (ADR-061).
3. Python šablony mají přímé závislosti v `requirements.in` a `requirements.txt`
   je z nich vygenerovaný `pip-compile` v obrazu `python:3.12-slim` šablony, se
   všemi tranzitivními balíčky. Verze: Django 5.2.18 (LTS), gunicorn 26.2.0,
   Flask 3.1.3, FastAPI 0.142.4, uvicorn 0.54.0.
4. Lockfily JavaScriptových šablon a Laravelu jsou aktualizované v mezích
   rozsahů z `package.json` a `composer.json`. `npm audit` ani `composer audit`
   v nich nenacházejí žádnou známou zranitelnost.
5. Dependabot hlídá pip a composer závislosti šablon. JavaScriptové šablony mají
   `package.json` jako Handlebars šablonu, takže Dependabot jim aktualizace
   nenavrhuje; jejich lockfily ale dostávají bezpečnostní upozornění z
   dependency graph GitHubu.

**Důsledky.** Nové projekty dostanou opravené soubory. Repozitáře existujících
projektů InitPad nemění; jejich vlastníci si mohou nové soubory převzít ze
šablony. Kdo v Python projektu změní `requirements.in`, musí znovu spustit
`pip-compile`; README šablon to popisuje. Django bez nastaveného
`DJANGO_SECRET_KEY` po restartu zneplatní podepsaná data, stejně jako Laravel
bez `APP_KEY`.

Zůstává: PHP šablony v produkčním obrazu stále používají vestavěný server
`php -S`, který je určený pro vývoj. Závislosti šablon se při vydání
nekontrolují automaticky, jen přes Dependabot. Obojí je samostatná budoucí
práce.

**Testování.** Živá zkouška s Gitea 1.22.6 a `act_runner` 0.2.13: workflow
šablony Flask prošlo a větev pojmenovaná `odd-'q"-$(id)` dorazila na platformu
jako obyčejný řetězec v JSON, nic se nespustilo. Testy Django, Flask a FastAPI
prošly s uzamčenými závislostmi v `python:3.12-slim` a gunicorn 26 obsloužil
`/health`. Všech pět JavaScriptových šablon prošlo `npm ci`, testy a buildem;
`npm audit` hlásí nulu. `composer audit` hlásí nulu pro Laravel, Nette a
Symfony. Instalaci balíčků Laravelu toto prostředí neumí (stahování z GitHubu
je blokované), test jeho obrazu proto proběhne v `container-images.yml` na PR.
Test kontraktu šablon ověřuje, že `${{ … }}` je jen v `env:`.

# ADR-151 — Záloha se šifruje veřejným klíčem, který server nedokáže otevřít

**Status:** Accepted

**Kontext.** `deploy/backup.sh` (ADR-062) ukládá databázi, repozitáře,
artefakty i celý `.env` se secrety jako nešifrovaný adresář. Dokumentace jen
doporučovala šifrovat zálohu ručně před kopírováním mimo server. Kdo získá
přístup k serveru nebo k místu, kam se zálohy kopírují, získá všechna data i
klíče. Audit z 9. října 2026 to vedl jako střední nález.

**Rozhodnutí.**

1. Když je nastaveno `INITPAD_BACKUP_AGE_RECIPIENTS_FILE`, `backup.sh` po
   vytvoření a ověření checkpointu zabalí adresář do jednoho souboru
   `<časové-razítko>.tar.age`, zašifruje ho pro veřejné klíče `age` ze souboru
   a nešifrovaný adresář smaže. Soubor vzniká s právy `0600` pod dočasným
   jménem a přejmenuje se až po dokončení.
2. Server dostává jen veřejné klíče. Soukromý klíč zůstává u správce mimo
   server, takže zálohu nerozšifruje ani útočník, který server ovládne.
3. Existenci souboru s klíči a nainstalovaný `age` záloha ověří ještě před
   zastavením služeb. Šifrování běží až po jejich obnovení, protože čte všechna
   data znovu. Když šifrování selže, nešifrovaný checkpoint zůstane a skript
   skončí chybou, aby se záloha neztratila.
4. `restore.sh` přijme i `.tar.age` s `INITPAD_BACKUP_AGE_IDENTITY_FILE`,
   rozbalí ho do dočasného adresáře s právy `0700` a ten smaže po úspěchu i po
   chybě.
5. Rotace (`INITPAD_BACKUP_KEEP`) počítá šifrované soubory i adresáře.
6. Šifrování je volitelné. Povinné by rozbilo existující plánované zálohy, které
   klíč nemají; bez něj skript na konci upozorní, že záloha obsahuje secrety
   nešifrovaně.

**Důsledky.** Šifrovanou zálohu lze bez obav kopírovat mimo server. Obnova
vyžaduje soukromý klíč; jeho ztráta znamená ztrátu všech záloh, proto ho správce
uchovává alespoň na dvou místech. Šifrování prodlouží zálohu o dobu jednoho
čtení dat, služby už ale v té době běží. Odeslání mimo server zůstává na
správci (`rclone`, `rsync`).

**Testování.** Test se skutečným `age` vytvoří klíče, zašifruje checkpoint s
tajnou hodnotou, ověří práva souboru, nepřítomnost tajné hodnoty v souboru,
odmítnutí přepsání existující zálohy, neúspěch cizího klíče a bajtově shodné
rozbalení. Kontraktní testy hlídají pořadí kontrol před zastavením služeb,
šifrování po jejich obnovení, rotaci obou forem a úklid rozbaleného adresáře.
Rotace byla ověřena nad vzorkem adresářů, šifrovaných souborů a logu. Celý
`backup.sh` a `restore.sh` nad běžící instalací v tomto prostředí neběžel.

# ADR-135 — Serverový profil posílá API z Caddy přímo, aby měla každá cesta jeden proxy hop

**Status:** Accepted

**Kontext.** ADR-102 počítá s tím, že self-hosted API má před sebou jen
vestavěný web proxy, a nastavuje `INITPAD_TRUST_PROXY_HOPS=1`. Serverový
profil ale před web proxy přidává Caddy. Cesta Caddy → web proxy → API má dva
hopy, takže API vidělo u každého požadavku adresu kontejneru Caddy. Limity
podle IP se tím staly společnými pro celou instanci: jedna třída, která se
přihlašuje současně, vyčerpala limit přihlášení pro všechny. Prosté zvýšení na
dva hopy nestačí. Web proxy zůstává publikovaný na portu 8080, protože ho
používají callbacky CI přes bránu sítě CI. Klient, který se připojí přímo,
by s nastavením na dva hopy mohl svou IP v `X-Forwarded-For` podvrhnout.

**Rozhodnutí.**

1. Caddy v serverovém profilu posílá `/api/*` přímo na `api:3000`, ostatní
   požadavky na web proxy. API tak má po každé cestě právě jeden proxy hop:
   Caddy, nebo web proxy pro přímý provoz a CI. `INITPAD_TRUST_PROXY_HOPS`
   zůstává `1` v lokální i serverové instalaci.
2. Caddy nemá `trusted_proxies`, takže hlavičku `X-Forwarded-For` od klienta
   vždy nahradí skutečnou adresou. Ověřeno živě s připnutým Caddy 2.11.4.
3. Obě domény posílají `Strict-Transport-Security`, takže prohlížeč po první
   návštěvě nepoužije pro doménu nešifrované spojení, ani přes port 8080.
4. Porty 8080, 3001 a 8085 zůstávají publikované pro síť CI a lokální
   kontroly. Docker je publikuje mimo `ufw`, proto runbook popisuje jejich
   blokování na veřejném rozhraní v řetězci `DOCKER-USER` a instalátor na to
   upozorní. Instalátor znovu vytvoří Caddy jen při změně Caddyfile.

SaaS profil se nemění: veřejný edge → web proxy → API se dvěma hopy podle
ADR-102.

**Důsledky.** Limity podle IP na serverové instalaci rozlišují skutečné
klienty a podvržená hlavička je neobejde. Odpovědi API přes Caddy nenesou CSP
z web proxy; API si ostatní bezpečnostní hlavičky nastavuje samo a JSON
odpovědi CSP nepotřebují. Zablokování přímých portů zůstává na provozovateli.
Úplné odstranění publikovaných portů vyžaduje převést callbacky CI na
interní adresu v síti CI, což je samostatná změna.

**Testování.** Kontraktní test hlídá směrování `/api/*` na API před web
proxy, výchozí jeden hop v Compose, absenci `trusted_proxies` a HSTS pro obě
domény. `caddy validate` s připnutým obrazem konfiguraci přijímá a živý test
potvrdil nahrazení podvrženého `X-Forwarded-For`.

# ADR-177 — Mazání projektu se zámkem a bez nasazení mimo cíl

**Status:** Accepted

**Kontext.** Smazání projektu během běžícího deploye rušilo jen operace bez
vlastníka (`executionOwner: null`). Executor proto dokončil nasazení a nechal
osiřelý workload. Mazání nemělo zámek, takže dvojklik spustil dva teardowny.
Prostředí, jehož server byl smazán (`targetId: null`, provider `docker`), se
nasadilo na Docker hostitele InitPadu bez limitů a allocation. Lease
provisioningu se během dlouhých kroků neobnovovala, `reconcileStale` běžel při
každém GET a mohl označit vlastní živou operaci za přerušenou. `succeed/fail`
pak výsledek přepsaly.

**Rozhodnutí.**

1. `Project.deletionStartedAt` (aditivní migrace) je compare-and-set zámek.
   Druhé mazání skončí 409 „already being deleted“. Zámek starší než 30 minut
   lze převzít. Při chybě mazání se zámek uvolní.
2. Pokud operace projektu drží živou execution lease, mazání ji označí
   `cancelled` a odmítne se (409) s výzvou smazat projekt znovu, až doběhne.
   Executor po návratu z provideru zrušení uvidí a nový workload odstraní.
   Lease s prošlou platností se uvolní a operace se dokončí jako zrušená.
3. Během mazání `begin` nezačne žádnou novou operaci.
4. Prostředí bez serveru odmítne `begin` (kromě `stop` a `remove`) i executor
   se srozumitelnou hláškou. Uživatel mu musí vybrat server.
5. Smazání serveru vypíše prostředí, která na něm mají nasazení. Prázdná
   prostředí odpojí automaticky, u aktivního serveru stejně jako u odpojeného.
   Kontrola uvnitř transakce brání odpojení prostředí, na kterém mezitím začal
   deploy.
6. Provisioning: lease se obnovuje časovačem každých 60 s po celou dobu create
   i import. `step/succeed/fail` platí jen pro vlastníka lease. Čtecí cesty
   spouští reconcile nejvýš jednou za 30 s a nikdy neoznačí operaci, kterou
   tento proces právě vykonává. Souběžné založení stejného jména nebo import
   stejného repozitáře se živou lease skončí 409. Import provisioning nese
   název repozitáře. Odmítnutý retry uvede skutečný důvod.

**Důsledky.** Smazání projektu během deploye vyžaduje druhý pokus po jeho
doběhnutí. Prostředí odpojené od serveru nejde nasadit, dokud nedostane nový.

**Testování.** Jest testy pokrývají zámek, zrušení operace executoru,
odmítnutí nové operace při mazání, odmítnutí prostředí bez serveru,
obnovování a fencing lease, rezervaci jména a hlášky mazání serveru.

# ADR-176 — Žádná lokální kopie repozitáře a omezené čekání na vzdálené služby

**Status:** Accepted

**Kontext.** Import ukládal do `Project.repoPath` relativní `owner/name`.
Smazání projektu pak volalo `rmSync` na tuto cestu vůči pracovnímu adresáři
API (`/repo/apps/api`), takže uživatel `dist` nebo `prisma` smazal části API.
Stejná hodnota sloužila jako záložní zdroj deploye přes `git archive`.
Zakládání projektu zároveň sdílelo checkout `.workspace/<user>/<name>`, takže
dvojklik „Vytvořit“ zničil i první požadavek. SSH spojení, příkazy `git` a
klient S3 neměly žádný časový limit. Tichý protějšek tak nechal deploy nebo
zakládání viset navždy, zatímco se lease operace dál obnovovala.

**Rozhodnutí.**

1. Zdrojem pravdy pro kód je vždy SCM. Nové projekty ukládají `repoPath = ''`.
   Příprava deploye stahuje přesný commit přes `downloadArchive` a nikdy
   nepoužije uloženou cestu. `source-export.ts` byl odstraněn.
2. `downloadArchive` při chybě vyhodí konkrétní důvod (HTTP stav, chybějící
   commit, chyba rozbalení) místo `null`. SFTP proto už nehlásí zavádějící
   „Artifact directory '.' does not exist“.
3. `rmSync` uložené cesty proběhne jen pro absolutní cestu uvnitř
   `config.workspaceDir` (`isWorkspaceCheckout`). Starší řádky s relativní
   cestou zůstávají v DB beze změny a mazání je bezpečně přeskočí. Žádná
   datová migrace není potřeba.
4. Každé založení renderuje šablonu do vlastního adresáře
   `.workspace/<owner>/<name>-XXXXXX` (`mkdtemp`) a po dokončení ho smaže.
5. Časové limity, všechny konfigurovatelné:
   - `INITPAD_GIT_TIMEOUT_MS` (120 s) pro každý příkaz `git`,
   - `INITPAD_SSH_KEEPALIVE_INTERVAL_MS` (15 s, spojení padne po 4
     nezodpovězených keepalive),
   - `INITPAD_SFTP_DEPLOY_TIMEOUT_MS` (15 min) pro celý SFTP deploy po
     navázání spojení. Po vypršení se spojení zničí a deploy selže s
     hláškou, která limit pojmenuje.
   - `INITPAD_ARTIFACT_S3_CONNECTION_TIMEOUT_MS` (10 s) a
     `INITPAD_ARTIFACT_S3_REQUEST_TIMEOUT_MS` (120 s nečinnosti socketu)
     přes `NodeHttpHandler`.

**Důsledky.** Projekt, jehož repozitář v SCM zmizel nebo je nedostupný, nejde
nasadit ani ze staré lokální kopie. Chyba ale řekne proč. Dlouhé uploady nad
15 minut je třeba povolit zvýšením limitu.

**Testování.** Jest testy pokrývají relativní i vnější cestu při mazání,
šíření chyby stahování, unikátní checkouty, keepalive, deadline SFTP,
timeout `git` a konfiguraci S3 handleru.

# ADR-159 — Čtení commitů a stavu pipeline z GitHubu šetří limit instalace

**Status:** Accepted

**Kontext.** ADR-132 uvedl, že čtení commitů a stavu pipeline se neukládá do
cache a že se proto jako první vyčerpá hodinový limit GitHub API jedné
instalace. Detail projektu čte 20 commitů a pro každý z nich seznam jobů
poslední CI běhu. Jedno otevření tak stojí 1 dotaz na commity a 20 až 40 dotazů
na běhy a joby (dva na commit, pokud není znám `runId`, jinak jeden).
Aktivita pracovního prostoru dělá totéž s 5 commity na projekt.

Zvažované možnosti:

- Cache dokončených běhů v databázi. Odmítnuto, vyžaduje migraci a nový zdroj
  pravdy kvůli optimalizaci.
- Webhooky `workflow_run` a `workflow_job`. Odmítnuto, endpoint zpracovává jen
  životní cyklus instalace a UI by záviselo na doručení událostí.
- Cache v paměti procesu s podmíněnými dotazy. Zvoleno.

**Rozhodnutí.** Adaptér GitHubu (`GitHubScmProvider`) drží dvě omezené cache
v paměti procesu (`ReadCache`, nejstarší záznam se vytlačí, platnost je
omezená):

1. Joby běhu, jehož všechny joby jsou `completed`, se ukládají na 15 minut pod
   klíčem repozitář, SHA a `runId`. Dokončený běh se už nemění, další čtení
   proto GitHub nezatíží. `rerunFailedJobs` záznamy repozitáře maže, protože
   běh získá nový pokus.
2. Čtení commitů, vyhledání běhu podle SHA a jobů neukončeného běhu posílá
   `If-None-Match` s posledním `ETag`. Odpověď `304` GitHub nezapočítává do
   primárního limitu a adaptér vrátí uložené tělo. Záznamy platí hodinu.

Cache slouží jen jako optimalizace. Chybějící záznam, vytlačení, restart nebo
jiná replika (viz volba leadera řídicí roviny) znamenají jen víc dotazů a nikdy
jiný výsledek. Tělo z `ETag` cache se použije jen po `304` na dotaz s platným
installation tokenem, takže kontrola přístupu zůstává na GitHubu. Cache
dokončených běhů se nedotazuje na GitHub, přístup k projektu ale dál hlídá API.
Installation token se nadále neukládá (ADR-043). Gitea adaptér se nemění.

**Důsledky.**

- Opakované otevření detailu s dokončenými běhy stojí 0 dotazů na joby a
  1 podmíněný dotaz na commity; poprvé zůstává 1 + 2 × 20 dotazů.
- Běh znovu spuštěný přímo v GitHubu se v InitPadu může až 15 minut ukazovat
  jako dokončený.
- Každá replika má vlastní cache, úspora tedy roste s afinitou požadavků.
- Instalační token se dál vydává při každé operaci; jeho cache vyžaduje
  samostatný ADR.

**Testování.** Jednotkové testy `github-scm.provider.spec.ts` ověřují, že
dokončený běh se podruhé nečte, že re-run cache zneplatní a že `If-None-Match`
a `304` vrací stejná data pro commity i joby. `github-read-cache.spec.ts`
pokrývá platnost, limit velikosti a mazání podle prefixu. Dopad na skutečný
limit zůstává mimo měření load acceptance z ADR-124.

# ADR-121 — OAuth state a OIDC granty jsou hashované a trvalé

**Kontext.** GitHub OAuth `state` byl podepsaný a časově omezený, ale login
a link flow neměly serverový jednorázový záznam. Interní OIDC provider pro
Giteu držel authorization codes a access tokeny v mapách jednoho API procesu.
Restart mezi authorize a token requestem proto zneplatnil SSO a load balancer
nemohl bezpečně poslat jednotlivé kroky na různé repliky.

**Rozhodnutí.** GitHub state zůstává HMAC-podepsaný a svázaný s HttpOnly
double-submit nonce cookie. Při vydání se navíc uloží jeho SHA-256 do
`ExternalOAuthState`; callback nejprve ověří podpis, stáří a cookie a teprve
potom atomicky nastaví `usedAt`. Chybná nebo chybějící cookie state
nespotřebuje.

OIDC authorization codes a access tokeny se vydávají jako kryptograficky
náhodné hodnoty, ale PostgreSQL uchovává pouze jejich SHA-256 v `OidcGrant`.
Authorization code se atomicky označí jako použitý; access token lze číst do
expirace. Každé použití je nadále svázané s aktuálním `User.tokenVersion`, takže
deaktivace, reset nebo rotace sessions grant okamžitě odvolá. Expirované
záznamy se oportunisticky odstraňují při vydání další hodnoty.

**Proč.** Databáze už je sdílená autorita pro sessions, rate limiting a
identity. Nové tabulky odstraní sticky-session požadavek bez zavedení další
stavové služby a při úniku databáze neposkytnou použitelné browserové ani
bearer tokeny.

**Důsledky.** OAuth/OIDC flow nyní vyžaduje dostupnou PostgreSQL; to odpovídá
existující readiness hranici API. OIDC signing key musí při více replikách
pocházet ze stejného chráněného souboru nebo secret mountu. Tento krok neřeší
produkční e-mail, tenant kvóty, scheduler ani samotné horizontální nasazení.

**Testování.** Unit testy používají dvě instance služby nad jedním
databázovým test doublem: druhá replika spotřebuje state/code vydaný první,
replay selže a access token zůstane dostupný. Testy zároveň dokazují, že
databázové klíče jsou 64znakové SHA-256 hashe a chybná nonce platný state
nespotřebuje. Controller testy zachovávají lifecycle a callback regresi.

# ADR-148 — Obnova účtu odvolá všechny Gitea tokeny a provoz umí ukončit Gitea sessions

**Status:** Accepted

**Kontext.** Obnova hesla, reset hesla administrátorem a deaktivace účtu
odvolávaly jen Git token, který vydal InitPad (ADR-134). Kdo měl převzatý účet,
mohl si přes Gitea webovou session vytvořit vlastní access token nebo z upraveného
workflow přečíst registry token repozitáře; obojí obnova účtu nechala platné.
Audit z 9. října 2026 navíc uvedl, že Gitea webová session přežije reset hesla
v InitPadu.

Zkouška nad Gitea 1.22.6 ukázala, že Gitea nemá API pro ukončení webové
session uživatele. Změna hesla administrátorem session ponechá. Deaktivace a
zákaz přihlášení ji blokují jen po dobu, kdy platí; po opětovné aktivaci tatáž
session znovu funguje. Gitea v obrazu drží sessions v paměti, takže restart
kontejneru ukončí všechny.

**Rozhodnutí.**

1. Obnova účtu (reset hesla uživatelem, reset administrátorem, deaktivace)
   smaže všechny access tokeny Gitea účtu bez ohledu na jméno, tedy i tokeny,
   které vytvořil uživatel nebo útočník přímo v Gitee. Registry tokeny
   repozitářů účtu potom vydá znovu a uloží do CI secretů, aby CI dál
   publikovalo; staré hodnoty přestanou platit. Když Gitea operaci nepotvrdí,
   reset selže a odkaz zůstane použitelný jako dosud (ADR-134).
2. Provozní postup pro převzatý účet v `deploy/OPERATIONS.md`: deaktivovat účet,
   restartovat Gitea, obnovit heslo a účet znovu aktivovat. Ostatní uživatelé se
   po restartu přihlásí do Gitey znovu přes InitPad, který už ukončené sessions
   odmítá (ADR-147).
3. Životnost Gitea session se nezkracuje. Gitea ji počítá od poslední aktivity,
   takže aktivní útočník by ji udržel i s kratší hodnotou, a uživatelé by
   častěji viděli přihlašovací stránku Gitey.

**Důsledky.** Token vytvořený během převzetí účtu obnovu nepřežije. Uživatel
po resetu hesla přijde i o tokeny, které si v Gitee vytvořil sám, a musí je
vytvořit znovu. Otevřená Gitea session útočníka trvá, dokud správce nerestartuje
Gitea; samotná deaktivace ji zablokuje, ale neukončí. Restart Gitey krátce
přeruší Git operace a CI klonování všech uživatelů.

**Testování.** Unit test ověřuje smazání všech tokenů účtu včetně tokenu
s cizím i InitPad jménem, opětovné vydání registry tokenu a jeho uložení do CI
secretu, a že účet, který Gitea nezná, obnovu nezastaví. Testy resetu hesla
ověřují, že se odvolání týká repozitářů účtu a že při nedostupné Gitee odkaz
zůstane nepoužitý. Chování Gitea sessions je ověřené proti Gitea 1.22.6:
session přežila změnu hesla i deaktivaci s opětovnou aktivací a skončila až
restartem kontejneru.

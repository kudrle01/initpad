# ADR-167 — Agent udržuje TLS edge brány aktuální

**Status:** Accepted

Doplňuje [ADR-165](./ADR-165.md) a [ADR-166](./ADR-166.md).

**Kontext.** Edge spravované brány (`initpad-gateway-edge`) i jeho Caddyfile
vytvořil jen instalátor. Aktualizace Agenta z GUI vyměňuje jen kontejner Agenta,
takže změna edge (například adresa ke stažení CA z ADR-166) se k serveru
nedostala, dokud správce znovu nespustil instalační příkaz. GUI přitom u
připojeného Agenta žádný takový příkaz nenabízí a nový token by byl zbytečný.

**Rozhodnutí.**

1. Image Agenta nese referenční Caddyfile edge (`gateway-edge.ts`); test hlídá,
   že je bajt po bajtu shodný s tím v `install.sh`. Instalátor edge označí
   štítkem `com.initpad.gateway.edge-config` s krátkým SHA-256 souboru.
2. Po startu Agent porovná štítek běžícího edge se svou verzí. Při rozdílu
   zapíše nový Caddyfile (starý uloží jako `Caddyfile.previous`) a edge znovu
   vytvoří se stejným image a nastavením.
3. Nenaběhne-li nový edge, Agent vrátí předchozí kontejner i Caddyfile. Chyba se
   jen zaloguje; Agent kvůli ní nepřestane pracovat.

**Hranice.** Agent sahá jen na kontejner `initpad-gateway-edge` se štítkem
instalátoru, jehož Caddyfile leží ve `/var/lib/initpad-gateway`. Používá image
tohoto kontejneru (musí být neměnný) a doménu čte z jeho prostředí. Soubor píše
krátkodobý pomocný kontejner bez sítě a bez dalších mountů. Nic z toho nepřidává
Agentovi nové oprávnění nad rámec Docker socketu, který už má.

**Důsledky.** Edge se při obnově na několik vteřin restartuje. Server, kde edge
vznikl před touto verzí, ho dostane po prvním startu Agenta 0.16; nový
instalační příkaz už není potřeba. Příkaz zůstává v GUI jako záložní cesta.

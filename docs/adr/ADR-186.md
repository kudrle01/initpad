# ADR-186 — Jedna Node LTS linie, deterministický PR gate a ověřené release image

**Status:** Accepted

**Kontext.** Audit 13. 11. 2026 našel v repozitáři a CI několik nesouladů.
Platformní image běžely na Node 26, CI, release workflowy, Supervisor a
`@types/node` na Node 22. PR gate spouštěl síťový `npm audit`, takže výsledek
záležel na stavu databáze zranitelností v danou chvíli, i když CONTRIBUTING
sliboval offline kontrolu. Bez `age` se test šifrovaných záloh tiše přeskočil.
Dependabot npm PR (mění `package-lock.json`, tedy všechny image) se slučovaly
automaticky bez buildu a Trivy skenu image, protože workflow kontejnerů byl
filtrovaný podle cest a nemohl být povinnou kontrolou. Release image se
Trivy neskenovaly vůbec. TypeScript existoval v pěti kopiích dvou verzí, API
image nesla Prisma engine cizí architektury (~28 MB) a Agent se pro arm64
sestavoval pod QEMU.

**Rozhodnutí.**

1. Jedinou linií je Active LTS Node 26. `.node-version` ji určuje pro všechny
   workflowy (`node-version-file`), Dockerfily, `engines` i `@types/node` hlídá
   `scripts/toolchain-consistency.test.mjs`. Dependabot ignoruje major verze
   Node ve všech Docker adresářích a u `@types/node`; přechod na další LTS je
   ruční změna na všech místech najednou.
2. PR gate je `npm run check` a `npm run check:compose`. `audit:dependencies`
   běží na `main`, každou noc a ručně. Název jobu „Build, test and audit“
   zůstává, protože je povinnou kontrolou ruletu `main`.
3. `check:compose` (`scripts/check-compose.mjs`) vykreslí self-hosted stack
   s `.env.example`, override vydání a všemi profily stejně jako CI a uklidí
   jen to, co sám vytvořil.
4. `age` instaluje jedna composite akce z připnutého release s kontrolou
   SHA-256. Chybějící `age` je lokálně varování a v CI (nebo s
   `INITPAD_REQUIRE_AGE=1`) chyba.
5. Workflow „Verify container images“ běží u každého PR, vstupy image pozná
   `scripts/container-image-inputs.mjs` a končí jobem „Container images“,
   který bez změněného vstupu projde jako no-op. Dependabot auto-merge zapne
   sloučení jen tehdy, když je „Container images“ povinnou kontrolou ruletu
   `main`; Compose služby zůstávají ruční.
6. Oba release workflowy skenují každý pushnutý digest pro amd64 i arm64
   připnutým Trivy se stejnou politikou jako CI (ADR-144) ještě před podpisem.
   Skenování je samostatný job `scan`, protože `verify` běží před buildem.
7. Agent se sestavuje stejným nativním builderem jako platforma. Release gate
   (`.github/actions/release-gate`) znovu spustí jen audit závislostí, pokud
   na stejném SHA úspěšně doběhla kontrola „Build, test and audit“ z GitHub
   Actions; v jakémkoli jiném stavu spustí celé `check:release`.
8. TypeScript je jen v kořenových devDependencies (6.0), Nest CLI ho sdílí
   přes override a build stage image instalují i kořen workspace.
   OpenTelemetry chodí v Dependabotu jako jedna skupina.
9. API image ponechá jen Prisma engine své architektury; schéma dál uvádí
   oba musl cíle.

**Důsledky.** Dokud správce nepřidá „Container images“ mezi povinné kontroly
ruletu `main`, Dependabot PR se neslučují automaticky. Release po zelené CI
neprovádí build a testy podruhé. Lokální vývoj vyžaduje Node 26.

**Testování.** `toolchain-consistency`, `ci-workflow`,
`container-image-workflow` a `platform-release-workflow` testy čtou YAML
parserem a hlídají invarianty; `check:compose` je testovaný s náhradním
`docker` v `PATH`. Build všech čtyř image a migrace API image proti dočasné
PostgreSQL prošly ručně.

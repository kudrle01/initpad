# ADR-178 — Druhý push během deploye čeká ve frontě, vyhrává nejnovější

**Status:** Accepted

**Kontext.** Když CI dokončilo build v době, kdy dev ještě nasazoval předchozí
commit, callback `/ci/deploy` skončil chybou 400 („already has an active
operation“) a build se ztratil. `begin()` navíc nejdřív vytvořil operaci a
teprve potom zjistil konflikt, takže historie nasazení se plnila řádky
„cancelled: Another operation is already active“.

**Rozhodnutí.**

1. `Environment` má sloupce `pendingCiVersion`, `pendingCiArtifactId`,
   `pendingCiArtifactDigest` a `pendingCiQueuedAt`. Úspěšný CI callback pro
   dev, který přijde během aktivní operace, se do nich uloží a přepíše
   případný starší čekající build (latest wins podle pořadí callbacků).
   Callback vrátí úspěch a `lastCommit` ukáže `ci: queued <sha>`.
2. Neúspěšný CI callback během aktivní operace nevytváří operaci. Jen
   aktualizuje `lastCommit`, aktivní nasazení i čekající build zůstávají.
3. `ProjectDeploymentOperations.begin()` odmítne známý konflikt ještě před
   vytvořením řádku (`ActiveOperationConflict`, stále HTTP 400 se stejnou
   hláškou). Závod mezi čtením a claimem v transakci se chová jako dřív.
4. Čekající build se spustí, jakmile operace uvolní prostředí:
   `complete()` volá posluchače, který spustí `drainPending()`. Uvolnění
   zapsaná mimo `complete()` (replay jobů Agenta) zachytí sweep údržby
   každou minutu. Claim čekajícího buildu je compare-and-set na
   `pendingCiQueuedAt` a `pendingCiVersion`, takže ho spustí jen jedna
   replika. GitHub artefakt se před spuštěním ověří znovu.
5. Pokud mezitím uživatel dev zrušil nebo odebral (`empty`), čekající build se
   zahodí. Pokud dev už běží přesně na tomto SHA, také se zahodí.

**Důsledky.** Push během deploye se neztratí a starší build nemůže přepsat
novější, protože ve frontě je vždy jen poslední. Pořadí určuje příchod
callbacků, ne čas commitu: CI běh staršího commitu, který doběhne později,
vyhraje. Porovnání předků v SCM by stálo další volání providera a pro jednu
výchozí větev to v praxi nehrozí. Web zatím frontu nezobrazuje, stav je vidět
jen v `lastCommit`. `Run again` zůstává jen pro stavy `empty` a `failed`.
Ztracený push řeší fronta, ne ruční opakování.

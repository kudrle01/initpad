# ADR-175 — Režimy sítě instalátoru, předběžné kontroly a oddělený dev stack

Rozšiřuje ADR-161.

**Status:** Accepted

**Kontext.** Instalátor znal jen „tento počítač“ a dva režimy s DNS. Škola nebo
VM bez DNS musela ručně upravit `.env` a změna portu v `.env` nepřepočítala
URL. Obsazený port se projevil až pádem v půlce instalace. Dev stack v
`infra/` sdílel s self-hosted stackem jméno Compose projektu i volumy, takže
`docker compose down -v` nad dev stackem mazal produkční data. Opakovaný běh
instalátoru navíc vždy restartoval Giteu a znovu buildoval image.

**Rozhodnutí.**

1. Režim sítě je uložen v `INITPAD_NETWORK_MODE` (`local`, `ip`, `domain`).
   Nový režim `ip` (`--ip ADDR` nebo volba 2 v průvodci) vyplní veřejné URL
   `http://ADDR:<port>`, interní adresy registry a runneru ponechá na loopbacku
   a host-gateway a nastaví `INITPAD_DEPLOY_BIND_ADDRESS=0.0.0.0`.
2. Každý běh instalátoru přepočítá všechny URL z uloženého režimu a aktuálních
   portů. Starší instalace bez režimu se rozpoznají podle URL, ručně složená
   konfigurace zůstane beze změny.
3. Před spuštěním čehokoli instalátor zkontroluje volné porty (web, Gitea,
   statický web `INITPAD_STATIC_WEB_PORT`, v režimu domény 80 a 443) a poradí
   volný port. Kapacitu hostu jen varuje; čerstvou instalaci odmítne jen při
   zjevném nedostatku (méně než 3 GiB RAM nebo 8 GiB volného místa).
4. Image platformy se buildí jen při změně zdrojů (hash `HEAD` a lokálních
   změn v `apps/`, `templates/` a lockfilech) nebo když chybí. Gitea se
   restartuje jen při změně toho, co si drží v paměti o SSO.
5. Dlouhé výstupy (build, CI image seed) jdou do `deploy/.runtime/logs/`, při
   chybě se vypíše jejich konec.
6. Dev stack v `infra/` má jméno projektu `initpad-dev`, vlastní volumy a porty
   (Gitea 3002, statický web 8086), takže běží souběžně se self-hosted
   instalací. `infra/dev-setup.sh` ho připraví celý: Gitea bez průvodce,
   servisní účet a token, S3, `apps/api/.env` a na Linuxu `host.docker.internal`.

**Důsledky.** Instalace pro LAN je jeden příkaz a změna portu jeden re-run.
Opakovaný běh bez změn nepřeruší běžící CI. Kdo dříve spouštěl dev stack se
jménem `initpad`, má stará data ve volumech `initpad_*`; nový dev stack je
nepoužívá.

**Testování.** Kontraktové testy instalátoru a živý průchod: čistá instalace,
druhý běh bez restartu Gitey a bez buildu, kolize portu a `reset.sh`.

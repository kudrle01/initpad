# ADR-185 — Web překládá hlášky API, sjednocuje pojmy a nevede do slepých uliček

**Status:** Accepted

**Kontext.** Audit z 13. 11. 2026 ukázal, že český web zobrazuje chyby,
stavové důvody (`statusReason`) a kroky operací anglicky, protože API nemá kódy
chyb. Toasty byly jediný kanál chyb a mizely za 4,5 s. Maintainer mohl přidat
Docker server, ale Agenta k němu připojit nesměl, a UI mu neřeklo proč.
Čekající schválení produkce šla najít jen podle čísla na přehledu. Ve
formulářích se ztrácela data a stránky měly závody mezi požadavky. UI navíc
pro jednu věc používalo tři slova (server, cíl, target) a položka menu
„Nasazení“ vedla na seznam prostředí.

**Rozhodnutí.**

1. **Katalog hlášek API.** `lib/api-messages.ts` mapuje známé anglické hlášky
   regulárním výrazem na klíč slovníku. Pojmenované skupiny se stanou
   parametry. Skupina `detail` se překládá rekurzivně, protože API vnořuje
   jednu hlášku do druhé („Cleanup failed: …“). Neznámá hláška zůstane
   v původním znění. Překlad se použije v `ApiError` (původní text zůstane
   v `apiMessage`), u `statusReason`, kroků operací, zakládání, úloh Agenta
   a varování importu. Seznam validačních chyb už nekončí jako „HTTP 400“.
   Český slovník katalogu leží v `i18n/cs-api.ts`. Test hlídá, že katalog
   pokrývá vybrané reálné hlášky a že je API pořád posílá ve stejném znění.
2. **Role a servery.** Docker server s Agentem přidává jen owner nebo admin
   workspace, tedy ten, kdo Agenta smí připojit. Maintainer v dialogu volbu
   Docker nevidí a dostane vysvětlení. U nezapsaného Agenta, kterého maintainer
   vidí, je místo slepé uličky stejné vysvětlení. SFTP server se po uložení
   rovnou ověří. Novému Agent serveru se registrační příkaz vytvoří
   automaticky a zavření dialogu s nepoužitým příkazem vyžaduje potvrzení.
3. **Toasty** jsou v `aria-live` oblasti, chyby mají `role="alert"` a zůstávají
   do zavření. Každý toast jde zavřít a při najetí myší nebo fokusu se odpočet
   pozastaví. Stejná hláška se nevrší.
4. **Čekající schválení.** Karta na přehledu vede na
   `/projects?filter=approvals`. Seznam projektů ukazuje odznak schválení na
   všech šířkách a Sidebar u Projektů ukazuje počet čekajících žádostí.
5. **Formuláře a závody.** Formulář nového projektu a importu se ukládá jako
   koncept do `sessionStorage`. „Přidat server“ otevře dialog na stránce
   Servery a po uložení vede zpět. Preflight importu běží sám s debounce
   a výsledek smí zveřejnit jen poslední běh (sekvenční čítač a AbortSignal).
   Detail projektu posílá AbortSignal, při přepnutí projektu ruší staré
   požadavky a šablony stahuje jen při změně `templateId`. Zakládání a import
   mají timeout 180 s. Po jeho vypršení web přesměruje na přehled, kde je
   zakládání vidět, místo nabídky opakování, které by narazilo na konflikt
   názvu. Historie nasazení se po chybě obnovuje s backoffem a ve skrytém tabu
   nepolluje.
6. **Pojmy.** Cíl nasazení je v celém UI **server** (en *server*, cs
   *server*). Pojem *target* zůstává jen v API a kódu. Dev, test a prod jsou
   **prostředí** (*environment*). Položka menu se seznamem prostředí se
   jmenuje **Prostředí** (*Environments*). **Nasazení** (*deployment*)
   znamená jen operaci nasazení a její historii.
7. **Výkon.** Český slovník se načítá přes `import()` jen v české relaci. Kód
   frameworku a UI knihoven je v samostatných chuncích `vendor-react`
   a `vendor-ui`. Vstupní chunk se zmenšil z 228,9 kB na 45,5 kB.
8. **Drobnosti.** Proměnné spravuje každý, kdo smí do projektu zapisovat
   (member a výš), stejně jako v API. Dialog proměnných ukazuje chybu
   s „Zkusit znovu“ a po změně nabídne „Znovu nasadit {env}“ (u produkce jako
   žádost). Odmítnutí produkce přijme nepovinný důvod (`note`, nejvýš 300
   znaků). Přesměrování na přihlášení nese `next`, i po vypršení session.
   Chyba načtení workspaces se ukáže s možností opakovat. Nový týmový workspace
   otevře nastavení se členy. Stránky nastavují `document.title`. Nápověda má
   téma `self-hosted` a odkazy na troubleshooting, rename-delete a sign-in.
   Aktivita používá `/activity/feed?scm=true` s varováními (při 404 starší
   `/activity`). Rollback nabídne výběr z `candidates`, pokud je API posílá.

**Důsledky.** Novou hlášku API je kvůli překladu potřeba přidat do katalogu.
Bez toho se zobrazí anglicky, ale nic se nerozbije. Klíče hlášek jsou anglické
texty API, takže změna znění v API vyžaduje změnu katalogu, na kterou upozorní
test. Klíče slovníku se kvůli pojmu „server“ přejmenovaly. Kdo má rozpracované
texty s „target“, musí je přejmenovat.

**Testování.** Vitest pokrývá katalog hlášek (překlad, záložní text a shodu se
zdrojem API), toasty, závod preflightu importu, abort a sekvenci v detailu
projektu, načítání šablon, dialog proměnných, odmítnutí s důvodem, filtr
schválení, roli v dialogu serveru, `next` při přihlášení, chybu workspaces,
backoff historie, kontrakt aktivity a výběr verze pro rollback.

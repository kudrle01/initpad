# ADR-149 — Sítě sdílené za jednou adresou mají vyšší limit na IP

**Status:** Accepted

**Kontext.** Limity citlivých operací (ADR-102) počítají pokusy na IP adresu a
na účet nebo token. Škola nebo firma za NAT ale posílá požadavky celé třídy z
jedné veřejné adresy. Třicet přihlášení za 5 minut nebo deset registrací za
hodinu tak vyčerpá jedna třída na začátku hodiny a ostatní dostanou `429`.
Limity byly v kódu a provozovatel je nemohl upravit. Audit z 9. října 2026 to
vedl jako nízký nález.

**Rozhodnutí.**

1. `INITPAD_RATE_LIMIT_SHARED_NETWORKS` obsahuje CIDR rozsahy IPv4 a IPv6
   oddělené čárkou. Pro klienta z takového rozsahu se limit na IP násobí
   hodnotou `INITPAD_RATE_LIMIT_SHARED_NETWORK_FACTOR` (výchozí 20, rozsah
   1–100). Platí pro všechny operace s limitem, protože všechny trpí stejně.
2. Limity na účet nebo token se nemění. Hádání hesla jednoho účtu ze školní
   sítě je proto omezené stejně jako odjinud.
3. API při startu odmítne neplatný rozsah, rozsah širší než /8 u IPv4 a /32 u
   IPv6 (pravděpodobný překlep, který by vypnul ochranu pro celý internet) a
   násobek mimo rozsah.
4. Klient se pozná podle adresy, kterou API odvodí s ohledem na
   `INITPAD_TRUST_PROXY_HOPS`. Adresa IPv4 zapsaná jako IPv6 (`::ffff:`) se
   porovnává jako IPv4.

**Důsledky.** Škola nastaví svou veřejnou adresu a třída se přihlásí bez `429`.
Útočník ze stejné sítě má na IP vyšší limit, ale na každý účet stejný jako
jinde. Ochrana proti rozesílání pokusů na mnoho účtů z jedné sdílené adresy je
o násobek slabší; provozovatel proto uvádí jen sítě, za kterými skutečně stojí
jeho uživatelé. Pevné limity jednotlivých operací zůstávají v kódu.

**Testování.** Unit testy ověřují shodu IPv4, IPv6 a IPv4 zapsané jako IPv6,
odmítnutí neplatných a příliš širokých rozsahů, kontrolu násobku při startu a
že guard pro sdílenou síť násobí jen limit na IP a limit na účet ponechá.

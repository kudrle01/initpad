# ADR-189 — Týmový workspace se připojuje ke GitHub organizaci a zve do ní členy

Upravuje ADR-044 a ADR-046, navazuje na ADR-188.

**Status:** Accepted

**Kontext.** Na SaaS stagingu skončila změna role člena týmu chybou 500.
Týmový workspace byl připojený k osobnímu GitHub účtu a API posílalo GitHubu
oprávnění `pull`, `maintain` nebo `admin`. GitHub je přijímá jen u
repozitářů organizace, osobní repozitář zná jen spolupracovníka se zápisem.
Role v InitPadu (viewer, member, maintainer, admin) se proto u osobního
účtu na GitHub promítnout nedají. Chyba od GitHubu navíc nebyla převedená na
HTTP odpověď a jeho vysvětlení se zahodilo. Ve stejném toku chyběly další
věci: přijetí pozvánky selhalo, pokud pozvaný neměl propojený GitHub,
založení projektu selhalo kvůli jedinému takovému členovi a propojení
GitHubu po vstupu do týmu nikdy nespustilo synchronizaci přístupu.

**Rozhodnutí.**

1. **Týmový workspace se připojuje jen ke GitHub organizaci.** Instalaci
   GitHub App na osobní účet pro týmový workspace API odmítne při dokončení
   setupu i při jeho obnově. Nový projekt v týmovém workspace nejde založit
   na osobním účtu (409) a import nabízí jen repozitáře organizací. Osobní
   workspace dál přijímá osobní účet i organizaci.

2. **Stávající týmový workspace s osobním účtem funguje dál, ale omezeně.**
   Projekty na osobním účtu se dál sestavují a nasazují. Dokud je workspace
   má, změna role, přidání člena, vytvoření i přijetí pozvánky vrátí 409 s
   výzvou připojit organizaci. Kontrola proběhne dřív, než se na GitHubu cokoli
   změní. Odebrání člena a odchod z workspace fungují, protože odebrat
   spolupracovníka jde i z osobního repozitáře.

3. **InitPad zve členy týmu do organizace.** Při přijetí pozvánky, změně role,
   založení projektu a po propojení GitHubu InitPad nejdřív zjistí členství
   uživatele v organizaci (`GET /orgs/{org}/memberships/{login}`). Jen když
   žádné není, pošle pozvánku s rolí `member`. Nastavení role `member`
   existujícímu vlastníkovi organizace by ho degradovalo, proto se existující
   členství nikdy nepřepisuje. Pozvánku člen přijme na GitHubu. Práva k
   repozitářům projektů dál určuje role ve workspace: viewer `pull`, member
   `push`, maintainer `maintain`, admin a owner `admin`.

4. **Z organizace InitPad odebírá jen ty, které do ní sám pozval.** Tabulka
   `GitHubOrgMembership` pro každou instalaci a uživatele ukládá, zda pozvánku
   poslal InitPad, stav (`pending`, `active`) a GitHub id a login. Login se
   ukládá, aby odebrání fungovalo i po odpojení GitHubu. Při odebrání z
   workspace se členovi vezmou práva k repozitářům projektů. Z organizace
   (včetně zrušení čekající pozvánky) se odebere jen tehdy, když ho pozval
   InitPad a žádný jiný jeho workspace stejnou instalaci nepoužívá.

5. **Člen bez propojeného GitHubu dostane přístup později.** Přijetí pozvánky
   i založení projektu ho přeskočí místo chyby. Po propojení GitHubu InitPad
   projde jeho týmové workspace a přístup udělí. Selhání nikdy nezruší
   propojení; zaloguje se jako `workspace.github_access.sync_failed` a admin
   ho zopakuje změnou role.

6. **GitHub App potřebuje oprávnění organizace `Members: Read and write`.**
   Instalační token pro operace s členstvím žádá jen `members: write` a
   `metadata: read`. Organizace nainstalovaná před tímto rozhodnutím musí nové
   oprávnění schválit. Do té doby GitHub token odmítne a API vrátí 409 s
   pokynem, co v organizaci schválit.

7. **Odmítnutý požadavek na GitHub nebo Giteu není 500.** Globální
   `ScmExceptionFilter` odpoví 502, při rate limitu nebo výpadku 503 a při
   timeoutu 504. Status od GitHubu se nepředává dál, protože jeho 401/403/404
   popisuje token platformy, ne oprávnění volajícího. Validační hlášku GitHubu
   (`message` a `errors[]`) API zkrátí na jeden řádek bez URL, nejvýš 200
   znaků, a připojí ji ke zprávě i do logu `scm.request_failed`.

**Důsledky.** Role v týmu odpovídají právům na GitHubu a GitHub už nehlásí
neplatné oprávnění. Nový tým potřebuje GitHub organizaci; bezplatná
organizace stačí. Každá organizace musí schválit nové oprávnění App, což je
jednorázový krok jejího vlastníka. Stav pozvánky do organizace InitPad
aktualizuje při každé synchronizaci, ne webhookem, takže přijetí na GitHubu
se v seznamu členů projeví až příští synchronizací. InitPad smí zvát do
organizace a odebírat z ní, ale nikdy nemění roli existujícího člena ani
neodebere někoho, koho sám nepozval. Self-hosted edice s Giteou se nemění.

**Testování.** Unit testy pokrývají odmítnutí osobní instalace pro týmový
workspace (setup, obnova, založení projektu, import, stav pro web), 409 u
změny role a pozvánky v týmu s osobním účtem bez volání GitHubu, pozvání do
organizace jen bez existujícího členství, zachování vlastníka organizace,
zapamatování pozvánky po jejím přijetí, odložený přístup bez propojeného
GitHubu, synchronizaci po propojení, odebrání z organizace jen pozvaného a
jinde nepotřebného člena i po odpojení GitHubu, 409 při neschváleném
oprávnění, převod chyb SCM na 502/503/504 s očištěnou hláškou a štítky stavu
GitHubu u členů ve webu. Ručně na stagingu: schválení oprávnění v testovací
organizaci, odmítnutí osobní instalace v novém týmu, pozvání člena bez
GitHubu, propojení, doručení pozvánky do organizace, změna role na viewer a
maintainer ověřená na GitHubu a odebrání člena.

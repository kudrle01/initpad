# ADR-120 — SaaS control plane má samostatný runtime profil

**Kontext.** `INITPAD_EDITION=saas` mění produktové chování API, původní
Compose stack ale stále obsahuje Giteu, MinIO, lokální CI runner, testovací
deployment targety, host Docker socket a self-hosted update Supervisor. Pouhé
přepnutí proměnné proto není produkční SaaS deployment profil.

**Rozhodnutí.** Veřejný control plane používá samostatný
`deploy/saas.compose.yml`, který obsahuje pouze digest-pinned API a web. Nemá
Docker socket ani vestavěné SCM, CI, object storage, databázi, targety, ingress
nebo updater. PostgreSQL, privátní S3-compatible bucket, edge a secrets dodává
provozní prostředí. Web se ve výchozím stavu váže pouze na loopback pro
navazující edge proxy.

SaaS API startuje fail-closed: vyžaduje kompletní GitHub App/OAuth konfiguraci,
veřejný HTTPS origin, callback na stejném originu, externí artifact store a
produkční secrets. `saas-check.sh` vykreslí Compose model bez vypsání jeho
environmentu a odmítne jiné služby nebo mutable image reference.

**Proč.** Samostatný manifest je menší a auditovatelnější bezpečnostní
boundary než sada profilů a override pravidel nad laboratorním stackem. Chyba
v aktivaci profilu tak nemůže omylem vystavit Giteu, MinIO nebo host Docker API.

**Důsledky.** Manifest je zatím staging contract, nikoli tvrzení o hotovém
veřejném SaaS. Před připojením nedůvěryhodných tenantů stále chybí konkrétní
secret-manager integrace, edge/WAF a egress policy, observability, kvóty, load
test a živé GitHub acceptance.

**Testování.** Unit testy odmítají neúplný, HTTP nebo cross-origin SaaS
bootstrap. Release-tools test hlídá dvouslužbový manifest bez self-hosted
závislostí a Docker socketu. `saas-check.sh` nad připraveným staging
environmentem ověří Compose render a immutable image reference.

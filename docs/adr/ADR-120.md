# ADR-120 — SaaS control plane má samostatný runtime profil

**Kontext.** `INITPAD_EDITION=saas` mění produktové chování API, původní
Compose stack ale stále obsahuje Giteu, MinIO, lokální CI runner, testovací
deployment targety, host Docker socket a self-hosted update Supervisor. Pouhé
přepnutí proměnné proto není produkční SaaS deployment profil.

**Rozhodnutí.** Veřejný control plane používá samostatný
`deploy/saas.compose.yml`, který obsahuje pouze digest-pinned API a web. Nemá
Docker socket ani vestavěné SCM, CI, object storage, databázi, targety, ingress
nebo updater. PostgreSQL, privátní S3-compatible bucket, edge a secrets dodává
provozní prostředí. Web se ve výchozím stavu váže pouze na loopback pro
navazující edge proxy.

SaaS API startuje fail-closed: vyžaduje kompletní GitHub App/OAuth konfiguraci,
veřejný HTTPS origin, callback na stejném originu, externí artifact store a
produkční secrets. Tajné hodnoty se do kontejneru promítají jako read-only
soubory a načtou se před databázovou migrací. Přímá hodnota a její `*_FILE`
varianta se vzájemně vylučují; relativní, nečitelný, prázdný nebo binární secret
zastaví start. Self-hosted profil může kvůli zpětné kompatibilitě dál použít
přímé environment proměnné. `saas-check.sh` vykreslí Compose model bez vypsání
jeho environmentu a odmítne jiné služby nebo mutable image reference.

**Proč.** Samostatný manifest je menší a auditovatelnější bezpečnostní
boundary než sada profilů a override pravidel nad laboratorním stackem. Chyba
v aktivaci profilu tak nemůže omylem vystavit Giteu, MinIO nebo host Docker API.

**Důsledky.** Manifest nepřenáší secret hodnoty přes Compose environment ani
je neukládá do `.env`; deployment dodává pouze cesty k projektovaným souborům.
Je to zatím staging contract, nikoli tvrzení o hotovém veřejném SaaS. Před
připojením nedůvěryhodných tenantů stále chybí konkrétní secret-manager
integrace, edge/WAF a egress policy, observability, kvóty, load test a živé
GitHub acceptance.

**Testování.** Unit testy odmítají neúplný, HTTP nebo cross-origin SaaS
bootstrap. Secret-loader test ověřuje multiline hodnotu, odstranění file
pointeru, kolize vstupů i propagaci exit kódu. Release-tools test hlídá
dvouslužbový manifest bez self-hosted závislostí, Docker socketu a přímých
secret hodnot. `saas-check.sh` nad připraveným staging environmentem ověří
Compose render a immutable image reference. `saas-acceptance.sh` následně
ověří skutečný public HTTPS endpoint, migrační stav a S3 round-trip. Explicitní
disposable-staging recovery drill uloží před provider backupem marker do
odděleného PostgreSQL schématu i S3 prefixu, po backupu přidá druhý marker a po
restore přijme jen stav, ve kterém oba systémy obsahují první marker a neobsahují
druhý. Úspěšný test dočasné markery odstraní; neúspěšný je zachová pro diagnózu.

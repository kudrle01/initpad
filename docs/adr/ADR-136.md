# ADR-136 — První administrátor vyžaduje instalační token a registrace je ve výchozím stavu uzavřená

**Status:** Accepted

**Kontext.** Podle ADR-040 a ADR-042 se první účet, který se na nové instanci
zaregistruje, stane administrátorem. Na serveru dostupném z internetu tak mezi
dokončením instalace a první registrací provozovatele mohl instanci zabrat
kdokoli. Vzorový `deploy/.env.example` navíc nastavoval režim `open`. Větev
instalátoru, která měla nastavit `admin-provisioned`, se proto při čisté
instalaci nikdy nespustila. Každý registrovaný uživatel přitom smí přes vlastní
workspace nasazovat kontejnery na vestavěný Docker host control plane.

**Rozhodnutí.**

1. Výchozí režim registrace je `admin-provisioned` v aplikaci, ve vzorovém
   `.env` i v Compose. Režim `open` zůstává volbou provozovatele. Instalátor na
   serverové instalaci s otevřenou registrací upozorní, že se kdokoli může
   zaregistrovat a nasazovat na host.
2. Instalátor generuje `INITPAD_BOOTSTRAP_TOKEN` (48 hexadecimálních znaků)
   stejně jako ostatní secrety a vypíše ho na konci instalace, dokud instance
   nemá žádný účet. Doplní ho i do starších instalací.
3. API vytvoří první účet jen tehdy, když požadavek obsahuje tento token.
   Porovnání proběhne v konstantním čase přes SHA-256 otisky. V produkci bez
   nastaveného tokenu API první účet odmítne s pokynem k nápravě. Lokální vývoj
   bez tokenu si ponechává dosavadní tok. Registrace má dál limity podle IP a
   e-mailu, takže token nelze uhádnout hrubou silou. Token kratší než 32 znaků
   API při startu odmítne.
4. `GET /api/auth/config` vrací `bootstrapRequired` a přihlašovací stránka
   nové instance otevře registraci s polem pro instalační token.

Existující instalace se nemění: mají účty, takže token se neuplatní, a jejich
`.env` si ponechává dříve zvolený režim registrace.

**Důsledky.** Čerstvě spuštěný server nemůže zabrat cizí uživatel a nová
instalace nedovolí anonymní registraci s nasazováním na host. Provozovatel musí
první účet vytvořit s tokenem z výstupu instalátoru; token zůstává v
`deploy/.env` a lze ho kdykoli znovu přečíst. Vestavěný Docker target je dál
dostupný každému workspace; omezení na workspaces schválené administrátorem je
samostatná budoucí práce.

**Testování.** Unit testy ověřují odmítnutí prvního účtu bez tokenu i s
chybným tokenem, úspěšné vytvoření administrátora se správným tokenem,
odmítnutí v produkci bez nastaveného tokenu, další registrace bez tokenu,
hlášení `bootstrapRequired`, výchozí režim a minimální délku tokenu. Webový test
ověřuje pole pro token a jeho odeslání.

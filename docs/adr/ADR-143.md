# ADR-143 — Jednorázové odkazy nesou token ve fragmentu URL

**Status:** Accepted

**Kontext.** Aktivační odkaz (platí 3 dny), odkaz pro obnovu hesla (1 hodina) a
odkaz pro ověření e-mailu (24 hodin) měly token v cestě:
`/activate/<token>`, `/reset-password/<token>` a `/verify-email/<token>`
(ADR-040, ADR-042, ADR-123). Prohlížeč posílá cestu serveru, takže se token
zapsal do access logu webového kontejneru, Caddy a v SaaS i edge vrstvy, odkud
ho mohl přečíst kdokoli s přístupem k logům a použít ho, dokud nevypršel.
Audit z 9. října 2026 to vedl jako střední nález.

**Rozhodnutí.**

1. API skládá odkazy jako `/activate#<token>`, `/reset-password#<token>` a
   `/verify-email#<token>`, v e-mailu i v odkazu, který správce zobrazí ručně.
   Prohlížeč fragment serveru neposílá, a proto se nedostane do access logů ani
   do hlavičky `Referer`.
2. Stránka token přečte z fragmentu a hned ho odstraní z adresního řádku
   (`replace`, bez nového záznamu v historii). Token tak nezůstane na obrazovce
   ani v adrese, kterou uživatel zkopíruje. API dostává token jako dosud v těle
   POST požadavku.
3. Bez tokenu, třeba po obnovení stránky, stránka požádá o otevření celého
   odkazu znovu a API nevolá.
4. Staré cesty `/<route>/:token` zůstávají a přesměrují na novou podobu, aby
   fungovaly odkazy odeslané před aktualizací. Jejich token už je v logu z
   prvního požadavku; po vypršení odeslaných odkazů (nejdéle 3 dny) je lze
   odstranit.
5. Strukturovaný logger API maskuje token v obou podobách.

**Důsledky.** Access logy, edge logy a hlavička `Referer` jednorázové tokeny
neobsahují. Token dál zůstává v e-mailu a v globální historii prohlížeče,
která zaznamená původní adresu; to omezuje jednorázovost tokenu a jeho
platnost. Obnovení otevřené stránky token ztratí a uživatel musí odkaz otevřít
znovu.

**Testování.** Unit test API ověřuje, že ruční aktivační odkaz má token jen ve
fragmentu a že jeho hash odpovídá uloženému záznamu, a že odkaz pro obnovu
hesla zařazený do e-mailu má stejnou podobu. Test loggeru ověřuje maskování
tokenu ve fragmentu. Webové testy ověřují, že stránka pošle token z fragmentu a
odstraní ho z adresy, že starý odkaz s tokenem v cestě dál funguje a že stránka
bez tokenu API nevolá.

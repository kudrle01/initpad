# ADR-137 — Mutace se session cookie vyžadují JSON a session cookie pod HTTPS nese prefix `__Host-`

**Status:** Accepted

**Kontext.** Session InitPadu je JWT v HTTP-only cookie se `SameSite=Lax`. API
nekontrolovalo původ požadavku a Nest ve výchozím stavu přijímá i těla
`application/x-www-form-urlencoded`. `SameSite` chrání jen před jinými
*sites*. Aplikace nasazená na jiném portu stejného hostu nebo na sousední
subdoméně, například přes managed gateway, ale patří do stejného site.
Formulář z takové aplikace proto mohl s cookie oběti odeslat změnu, třeba
přidat útočníka do workspace jako admina. Sousední subdoména navíc mohla
nastavit cookie pro nadřazenou doménu a podvrhnout přihlášení.

Vestavěné Docker aplikace se publikují na `http://<host InitPadu>:<port>`.
Cookies se mezi porty neoddělují, takže při provozu InitPadu přes HTTP prohlížeč
posílá session každé nasazené aplikaci. Na úrovni cookies to opravit nejde.

**Rozhodnutí.**

1. Middleware za parserem cookies odmítne s `403` každý požadavek `POST`,
   `PUT`, `PATCH` nebo `DELETE`, který nese session cookie a zároveň:
   - má `Sec-Fetch-Site` `same-site` nebo `cross-site`, nebo
   - nemá `Content-Type: application/json`.
   Takový požadavek z jiného originu vyžaduje CORS preflight a CORS povoluje
   jen origin InitPadu. Kontrola nezávisí na nakonfigurované veřejné adrese.
   Požadavky bez session cookie (CI, Agent, webhooky, OIDC klient Gitey)
   nenesou žádné oprávnění prohlížeče a kontrola se jich netýká. Webový klient
   už JSON posílá u všech požadavků.
2. Pod HTTPS se session cookie jmenuje `__Host-initpad_token`. Prohlížeč ji
   přijme jen od přesného hostu se `Secure`, `Path=/` a bez `Domain`, takže ji
   subdoména nepodvrhne. Nepřefixovaný název se pod HTTPS nečte, protože by ho
   podvržená cookie mohla nést. Po aktualizaci se proto uživatelé jednou znovu
   přihlásí. Přes HTTP zůstává původní název, protože `__Host-` tam nelze
   nastavit.
3. Když self-hosted instance běží přes HTTP a vestavěné aplikace sdílejí její
   host, API to při startu zaloguje a stránka Administrace to administrátorovi
   ukáže s nápravou: HTTPS (serverový profil) nebo jiný host aplikací přes
   `INITPAD_DEPLOY_PUBLIC_HOST`.

**Důsledky.** Aplikace na stejném site už nemůže měnit data jménem přihlášeného
uživatele. Klienti API, kteří posílají session cookie, musí u změn posílat JSON.
Únik session do vestavěných aplikací při provozu přes HTTP zůstává známým
omezením; odstraní ho jen HTTPS nebo samostatný host aplikací.

**Testování.** Unit testy ověřují blokaci formulářů a `text/plain` se session,
blokaci podle `Sec-Fetch-Site`, průchod JSON požadavků webu, čtení a požadavků
bez session, odpověď `403` a pořadí middleware za parserem cookies. Další testy
kontrolují název a atributy cookie pod HTTPS i HTTP a detekci sdíleného hostu.
Živá zkouška nad API a PostgreSQL potvrdila `403` pro formulář i `text/plain`
se session, úspěch JSON požadavku a nezměněné `401` na OIDC token endpointu
bez session.

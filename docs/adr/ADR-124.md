# ADR-124 — Load a SMTP outage acceptance jsou omezené staging gate, ne důkaz active-active mutací

**Kontext.** Veřejný SaaS potřebuje důkaz, že skutečný HTTPS edge obslouží
očekávané čtení přes více API procesů a že výpadek SMTP neznepřístupní API
ani neztratí autentizační zprávu. Samotné spuštění dvou replik ale neprokazuje
bezpečné souběžné vlastnictví periodického lifecycle, retention a recovery práce.

**Rozhodnutí.** SaaS acceptance má dva oddělené provozní gate:

1. omezený autentizovaný read-heavy load probe běží přes veřejné HTTPS,
   měří objem, chybovost, p50/p95/p99 a propustnost a vyžaduje odpovědi
   alespoň dvou API procesů;
2. dvoufázový SMTP outage probe ověří uložení šifrovaného retry a readiness
   při zablokovaném egressu, po jeho obnovení pak doručení a vymazání payloadu.

API vrací pro acceptance náhodné process-local `X-InitPad-Instance`. Hodnota
neobsahuje hostname, pod, region ani cloudovou identitu a po restartu se změní.
Load probe vytváří izolované DB fixtures jen po explicitním opt-in a odmítne
běh, pokud existuje aktivní provisioning nebo deployment operace. SMTP drill
používá nepoužívanou staging adresu a lokálně zapisuje pouze náhodný marker.

**Proč.** Výsledek je reprodukovatelný a ověřuje cestu, kterou použije uživatel,
ne interní port jednoho kontejneru. Zároveň explicitně neplete horizontální
read kapacitu s bezpečným souběžným vykonáváním mutací, které dosud není hotové.

**Důsledky.** Background lifecycle volí jediného leadera databázovým lease
(ADR-125), ale process-bound operace dosud nemají execution fencing. Do jeho
dokončení a živého ověření smí veřejný mutační control plane provozovat jedinou
API repliku. Dvě repliky jsou povolené jen na disposable, quiescent stagingu
během tohoto gate. Úspěch skriptu neuzavírá edge/WAF, egress, observability ani
GitHub/Agent E2E gate.

**Testování.** Unit/contract testy kontrolují omezené parametry a prahy, validní
HTTPS origin, počet procesů, bezpečný stav outboxu, pevnou sadu příkazů a
odmítnutí chybného vstupu před otevřením databáze. Živé důkazy vzniknou až
na konkrétním SaaS stagingu v lokálním `results.tsv`.

# ADR-184 — Převod vlastnictví workspace, odchod z něj a správa platformních rolí

**Status:** Accepted

**Kontext.** Audit z 13. 11. 2026 (P1.19, P3) ukázal, že týmový workspace má
právě jednoho vlastníka a nikdo ho nemůže vyměnit. Člen, kterého někdo
přidal, nemohl workspace opustit. Deaktivace vlastníka workspace zamkla a
platformní roli šlo nastavit jen při založení účtu. Přidání člena navíc
vracelo 404 nebo 409, takže šlo zjistit, které účty existují.

**Rozhodnutí.**

1. `POST /api/workspaces/:id/transfer-ownership` `{ userId }`: vlastník
   předá týmový workspace existujícímu administrátorovi workspace s aktivním
   účtem. Sám zůstane administrátorem. Platí limit vlastněných týmových
   workspace (ADR-154). Obě role mají v SCM stejné oprávnění, takže se
   přístup k repozitářům nemění. Změna se zapíše do auditu jako
   `workspace.ownership_transferred`.
2. `POST /api/workspaces/:id/leave`: odejít může kdokoli kromě vlastníka.
   Vlastník musí nejdřív vlastnictví předat. Odchod odebere přístup
   k repozitářům, u rolí s právem zápisu obnoví registry credential
   (ADR-134) a zapíše se jako `workspace.member_left`.
3. Deaktivaci vlastníka týmového workspace API odmítne (409). Chyba vyjmenuje
   dotčené workspace a nabídne převod vlastnictví nebo smazání workspace.
4. `PUT /api/admin/users/:id/platform-role` `{ platformRole }` přidělí nebo
   odebere roli administrátora. Řádky administrátorů se zamknou, takže
   posledního aktivního administrátora nejde degradovat ani při souběžných
   požadavcích. Změna se zapíše jako `user.platform_role_changed`. Web
   nenabízí degradaci sebe sama, stejně jako deaktivaci.
5. Přidání člena vrací stejnou odpověď (aktuální seznam členů) pro
   neexistující účet i pro existujícího člena. Web proto neříká „člen
   přidán“, ale „pokud účet existuje, je teď členem“.

**Důsledky.** Workspace nikdy nezůstane bez vlastníka. Přidání bez souhlasu
přidávaného zůstává: kdo účet přidá, ho po úspěchu uvidí v seznamu členů.
Pozvánky se souhlasem jsou samostatná, větší změna. Odpověď API ale už
neodlišuje neexistující účet od existujícího.

**Testování.** Jest pokrývá převod (role, osobní workspace, deaktivovaný
cíl), odchod, stejnou odpověď při přidání, ochranu posledního administrátora
a blokaci deaktivace. Vitest pokrývá UI převodu, odchodu a platformní role.
